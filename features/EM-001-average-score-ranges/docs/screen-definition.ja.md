# 画面に必要な内容 — EM-001

更新日：2026年10月22日。[ベトナム語版](screen-definition.vi.md)に対応する、設計に付随する文書。**Figmaは10月16日・21日にShiteへレビュー依頼済み（[スレッド](https://tryhand.slack.com/archives/C0BRGJA6XDE/p1791290107759389)）。スレッドにShiteの承認はまだない。**

## 1. ルールの設定

登録先項目、平均点の参照元（集計設定・時期・対象集団）、個人点の参照項目、条件と登録値、および判定順を指定する。登録先は数値型または選択肢型。

登録先の値の範囲と条件数を区別する。例えば登録先が1～5でも、マッピングは1・3・5だけを使用できる。条件の追加・削除で登録先の範囲を変更しない。独立した評価段階数の設定や、不一致時の最低評価の自動割当は設けない。

平均点の参照元には授業平均（順位集計で授業毎の集計を使う場合）と科目グループ（「{グループ名}平均」）も含む。選択肢型の登録値セルの先頭は「選択してください」（未使用セル）とし、「(空欄)」（空欄を登録）と区別する。平均点帯（範囲・行）は最大20、1つの範囲あたりの個人条件（条件列）は最大10、保存容量は最大65,000バイト（絞り込み条件を含む設定全体で使う）。画面の説明にこの三つの上限を示し、「合計200セル以内なら自由に組める」とは受け取られない表現にする。保存時のエラーは、範囲数の超過・条件数の超過・保存容量の超過を別の文言で示し、保存容量の超過では上限のバイト数を示す。**Shiteの指示（2026年11月13日）の反映状況：** 上記の画面説明と保存時エラーは、ローカルで実装・確認済み（2026年11月16日、コミット済み。[context 13.10](../CONTEXT.md)参照）。**2026年11月19日更新：** 上限を平均点帯20×個人条件10、保存容量65,000バイトに変更した（コミット済み）。数値は定数から表示するため、画面の説明・エラー文言・保存時の検証が同時に変わる。MWとの最終決定で変わりうる。表示名称は「平均点連動評価」、「丸め前」は「端数処理前の平均点」に変更済み（コミット済み）。表の見出しは「平均点帯」「個人条件」を使う。**個人条件の空欄の列は入力した位置を保つ**（2026年11月23日更新。Shiteの指示、11月19日）。空欄の列は設定の再表示（一覧）では空のセル、編集画面を開き直したときも空欄とし、「個人条件N」の番号は入力した位置とする。片方だけ入力した場合のエラーは、入力した列の番号で示す。対象時期と平均点の参照元の選択肢は、順位集計の学年・HR設定に関わらず表示する。

## 2. 設定の再表示

保存した参照元、条件、比較演算子、登録値、順序を再表示できること。レイアウト、入力部品、画面遷移はFigma設計時に具体化する。

## 3. 結果の確認

Q4に従い、成績抽出の度数分布表・グラフを使用し、人数確認用の画面は新設しない。2026年10月16日のローカル環境での確認では、数値型・選択肢型（A/B/C）の双方で表とグラフが出力され、人数が一致した。詳細は[context第10節](../CONTEXT.md)を参照。受入判定までに、staging、空欄の結果、およびEM-001の自動計算から成績抽出までの一連の動作を確認する。

参照元や一致した条件を説明する計算履歴の拡張は設計案であり、顧客から個別に要求・承認された画面ではない。
