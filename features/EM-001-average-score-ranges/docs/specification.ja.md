# 仕様案 — 平均点の範囲に応じた評価マッピング

更新日：2026年10月15日。[ベトナム語版](specification.vi.md)に対応する。[context](../CONTEXT.md)と[確認元](../sources/confirmed-business-qa.ja.md)を先に読む。本書はcontextの説明であり、独立した要求の根拠ではない。第1節は確認済みの原則、第2～3節は例、第4節は提案、第5節は共通仕様と運用案、第6節は未実施の検証事項。

## 1. 設定と計算

既存の登録先項目、平均点の参照元（集計設定・時期・集団）、生徒の数値項目を指定する。平均点で表の行を選び、その行の条件に個人点を当てはめて登録値を決定する。条件、演算子、登録値、順序を保存・再表示する。AutoRating実行時に算出・登録し、平均点または表の変更後に再計算できるようにする。

設定順に判定し、最初に一致した条件を採用する。不一致なら既存値があっても空欄に更新し、最低値を自動割当しない。登録先は数値型または選択肢型。登録値は選択した登録先に対応するが、入力方法と詳細な妥当性検証はこのスレッドでShiteが指定した事項ではない。

## 2. 数値項目で1・3・5だけを使う例

登録先は評定。有効な最小値1・最大値5で、他の設定による範囲変更はないものとする。**担当者の依頼による説明例であり、顧客の元の例を置き換えない。**

| 集団平均 | 個人点の条件（記載順に判定） |
| --- | --- |
| 0 ≤ 平均 <50 | ≥80 → 5; ≥65 → 3; <65 → 1 |
| 50 ≤ 平均 <70 | ≥90 → 5; ≥75 → 3; <75 → 1 |
| 70 ≤ 平均 ≤100 | ≥95 → 5; ≥85 → 3; <85 → 1 |

- 平均49・個人点85 → 5。平均60・個人点85 → 3。平均60・個人点30 → 1。
- 平均70・個人点70 → 1。対応する選択肢型の例ではCを登録する。
- LOGの例：1812 ÷ 30 = 60.4。平均は2行目に該当し、個人点85は条件2に一致するため、3を登録する。
- 不一致の別例：3行目の最後の条件を「<65 → 1」に変更すると、平均70・個人点70は既存値があっても空欄となる。これは上記モックアップとは別の設定である。
- 2・4は登録先の範囲内だが、この表からは出力されない。
- 条件の追加・削除で1～5の範囲は変わらない。条件数を5にする必要はない。

元の顧客例は別の表であり、平均60・個人点85 → **4**。Q2の例は**2・4・5**を使う。これらを同一設定として扱わない。

## 3. 選択肢型の例

担当者の依頼により、2026年10月15日に説明用の表を[Figmaモックアップ](https://www.figma.com/design/ECOs3PWUGyxIS6LS0MnTjm?node-id=63-23)と同期した。顧客による設計承認を意味しない。

第2節と同じ説明用閾値を用い、出力5・3・1をそれぞれA・B・Cにした別設定を例とする。これは登録先の型の違いを示すもので、システム共通のA=5/B=3/C=1という換算規則ではない。選択肢の保存値と表示名は同一とは限らず、保存値を判定元の点数として扱わない。

## 4. レビュー対象の設計案

**本節全体は提案または技術的な確認事項であり、Shiteによる追加承認ではない。** 第1節の「最初の一致」「不一致は空欄」は確認済みであり、以下の二段階の詳細を検討することによって未確認へ戻すものではない。

- 登録先の型・範囲に合わせた値の検証を提案する。範囲外の設定を拒否するか、保存時に結果を制限するかは現状と照合する。顧客承認済みのvalidationと扱わない。
- 平均点の範囲をANDで結ぶ二つの比較で表し、二つ目は省略可能とする案。行には順序を設ける。**最大二条件という業務制限が承認されたわけではない。**
- 平均点条件の値を取得できない行は不一致として次の行を判定する。どの行/条件にも一致しない場合は共通原則に従い空欄とする。[RA-001 Q7](../../RA-001-ranking-average/sources/2026-10-09-business-questions.ja.md#q7)から継承する規則であり、EM-001スレッドでShiteが個別に確認した内容ではない。
- 最初に一致する平均点行を選び、その行の個人点条件だけを判定する案。個人点が不一致の場合に後続の平均点行へ戻らず空欄とする部分は、レビューが必要な設計解釈であり、Shiteの個別確認事項ではない。
- 個人点が空欄なら結果も空欄という補足はチーム回答に基づく。0は空欄ではない。
- 現在設定中の項目を登録先とし、別の登録先選択欄は追加せず、二段階用の新しい登録方法を追加する案。UI案でありQ2の承認事項ではない。
- 一覧・ログで順序、実際に使用した参照元、一致条件、結果を示す案。保存形式とログ詳細は未確定。
- 書込権限、手動変更セル、保存前の有効な最小・最大値の扱いは既存の動作を維持し、実装時に現状と照合する。

## 5. 平均点の参照元と運用

[RA-001共通仕様](../../RA-001-ranking-average/docs/specification.vi.md)に従い、丸め前の合計点÷同じ版の得点がある生徒数を使用し、`examinees`は使わない。1,812÷30=60.4の30は得点がある生徒数。確定版の方針はRA-001の未回答Q2に従う。現行の案Aでは、確定範囲内で必要な集団が欠けても最新値へフォールバックしない。分母0も平均点なしとする。平均点条件で値を取得できない場合は不一致として次の条件を判定し、どの条件にも一致しなければ空欄とするRA-001 Q7の共通規則を継承する。context第4節を参照。

運用案：表だけを変更した場合は保存後、影響範囲のAutoRatingを実行する。元の点数が変わった場合は共通方針に沿って集計・確定版を更新して再計算する。このスレッドは個々の書込経路の自動起動を確認したものではない。

## 6. 必要な検証

境界・演算子、重複と順序、不一致時の既存値消去、空欄と0、数値項目の1・3・5のみの使用、選択肢、保存・再表示、集団・版・分母、書込権限、再計算を確認する。Q4の既存度数分布をstagingで試す。検証予定であり、Test Specや実行済みテストではない。
