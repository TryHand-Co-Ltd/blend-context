# DEC-004 — 赤点判定は確定済みの集計結果だけを getTotalResults() で読む

日付：**2026年10月28日**。対象：RC-001（RA-001・EM-001も同様）。根拠：shite氏との合意（2026年10月）— ①②③は確定済みの順位集計結果だけを使う。PR [#57058](https://github.com/ednity/school-web/pull/57058)。

| 項目 | 内容 |
| --- | --- |
| 決定 | 赤点判定は、学年×時期の有効な**確定済み**集計結果だけを `GradeCalcResultService::getTotalResults(..., $use_fix_table = true)` で読む。未確定・確定解除は判定不能（データなし）。未確定の最新集計結果は使わない。平均は `total_score ÷ student_count`（丸めない）、集団得点率は `total_score × 100 ÷ max_score`。参照元IDは有効な確定ログのID。 |
| 置き換える定義 | 旧ルール「確定済みを優先し、未確定なら最新の完了済み集計を使う」（仕様 §5.5、AC-G13、Q&A、TC-RS-BR-008） |
| 影響 | 仕様・画面定義・受入基準・DB設計（`kind` は `confirmed` のみ）・タスク分割・テストケース・テストデータを更新。運用手順に、緑ボタンと橙ボタンの間の**確定**を追加 |
| 状態 | shite氏と合意済み。顧客提出文書としての承認ではない |

## 未確定事項（文書は未変更）

- ~~shite氏の依頼1~~ — **確定（2026-10-28、shite氏）：** 「参照元と判定対象を同じ評価項目に限る」制約を外す。平均点は選択した順位集計設定の確定済み結果のみ使用。参照元・履歴には #57058 の共通メソッドが返す実際の項目IDを記録。対象項目を変更しても再集計・確定更新前は以前の確定結果をその実際の項目として使う。IDが取得できない場合は不明として扱い（判定は続け、`null` で保存）。外すのは評価項目の制限のみで、科目・単元は変更なし。spec §5.4–5.5、AC-G13、DB設計、TC-RS-BR-041 に反映済み。
- 確定後に設定を変更した場合の警告（倉島氏、PR #57058）：未push。確定後に文書を更新する。
- `evaluate_item_id` 列の追加前に作成された授業ごとの集計行は値が空の場合がある。空は「不明」として扱う。

## 理由

赤点は担当者が確定した数値に基づくべきで、順位平均・平均点範囲マッピングと同じ読取り経路にそろえる。未確定の結果は集計のたびに値が変わるため使わない。
