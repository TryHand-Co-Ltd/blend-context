## 保存済み設定の扱い（追補）

- 旧形式（`version` なし）は、条件欄を変えない保存（名称・基準だけの変更を含む）では保存済みのJSONと判定をそのまま残し、`version: 2` へ変換しない。
- 同じ種類で複数 key を持つ旧条件（従来はOR）の条件欄を変更して保存する場合は、ORがANDに変わることの確認チェックを必須とし、サーバーでも検証する。
- 保存済みの条件が読み取れない（JSON不正・未知の種類）場合は、この画面からの保存を拒否し、条件を消さない。
- 旧形式の条件を変えない保存では、新しい重複規則などの条件検証を行わない（旧データが保存できなくなることを防ぐ。名称は検証する）。
- 旧 HR・授業条件は、保存済みの値だけ残せる。別の値への差し替え・追加はサーバーで拒否する。
- 旧形式の HRコース（hr_course）、filters 内や type キーの平均点・集団得点率も読み取れる条件として扱う。マスタカリキュラム（旧称「授業カリキュラム」。画面の項目名を実データに合わせて変更）の指定が違う教科・科目の行は別の条件欄とし、重複扱いにしない。保存済みのマスタカリキュラムが現在の一覧に無い場合も、選択肢「（選択不可）（複数あるときは①②の番号で区別する。ID は画面に出さず、title にだけ持たせる。画面に案内文も表示する）」として残し、保存で条件を消さない（新しく一覧に無い値を指定することはできない）。
- 保存済みの値が現在の選択肢に無いとき（廃止された学年・HRコース・成績グループ項目・選択肢、集計条件の時期・順位集計設定など）も、画面を開いた時点で値を捨てない。「（選択不可）（複数あるときは①②の番号で区別する。ID は画面に出さず、title にだけ持たせる。画面に案内文も表示する）」の項目として表示し、チェックが付いたまま送信する。旧形式の条件を変えない保存は、保存済みの内容をそのまま残して保存できる。version 2 や他の項目を変える保存でも、保存済みの値は種類を問わず検証で残せる（マスタカリキュラムと同じ扱い）。保存済みに無い一覧外の値を新しく指定する保存は拒否し、理由を表示する。利用者が項目のチェックを外したときだけ、その値を外して保存できる。一覧に無い値だけの条件欄は判定で誰にも一致しない（判定は保存前後で変わらない）。集計条件の時期・順位集計設定・母集団が選べない値のときは「現在選択できません。選び直してください。」と案内する。
- 判定では教科・科目の行（教科の行、科目の行、旧形式の単独項目 subject_id / sub_subject_id、マスタカリキュラムが違う行）はすべて同じ種類として OR で扱う（version を問わない）。複数の行がある設定には「どれか1つに当てはまれば対象」の案内を出す（マスタカリキュラムは1行に1つしか選べず行をまとめられないため、まとめる案内は出さない）。旧形式で教科・科目以外の同じ種類の行が複数ある設定には「これまでは『いずれか』で判定」「1つの行にまとめてください」の案内を出す。案内は入力エラーで画面に戻ったあとも出し続ける（保存済みの条件についての案内を、送信内容ではなく保存済みの設定から作る）。
- 閾値設定の固定点数の確認（0 ≤ 基準点 ≤ 対象授業の有効満点の最小値）は、同じ生徒が適用条件（学年・HRコース・HR・成績グループ・組合わせ・選択肢型）の全部に当てはまる授業だけを対象授業とする。条件ごとに授業を絞るだけでは、「生徒Aは①だけ、生徒Bは②だけ」の授業も対象になり、対象外の授業の満点で正しい基準点が拒否される。生徒が1人もいない授業は、適用条件が無い場合も対象授業にしない。HR学年・HR・HRコースの判定は、授業とHRの結び付き（授業HR）ではなく、生徒本人のHR所属で行う（授業HRが別学年でも、その授業に該当学年の生徒がいれば対象）。授業の絞り込みは、生徒の所属情報を1回だけ読み込む生徒単位の1段階で行う。
- 読み取れない条件では保存ボタンを出さない。
- 教科・科目のモーダルは自動計算設定と同じ形（「教科で絞り込む」「科目で絞り込む」のどちらか一方を選ぶ）。1つの条件欄では教科か科目の一方だけを保存し、両方を送ると拒否する。教科と科目の両方を持つ保存済みの条件は、判定（いずれかに一致）を変えないよう、教科の欄と科目の欄に分けて表示する。
