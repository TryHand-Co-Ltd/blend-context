# 赤点 — 対応内容と作業分担

**更新日:** 2026年9月28日。

**v2 / Draft:** 公開表示の保存、セル世代・版数による同時更新制御、確認済みの母集団選択動作を追加した作業分担案。実装済みの報告ではない。

数値の評価項目に複数の赤点ルールを設定し、保存された最終点数を判定する。保存済みの同じ判定結果を、成績抽出・成績公開・通知表ツールでそれぞれの表示設定に従って利用する。対象は数値入力（整数・小数）と単元の数値項目。通常の教員も、機能へのアクセス権と対象項目の編集権があれば設定できる。

本書は**機能全体の作業分担案**であり、全機能の実装・リリース承認ではない。固定点数は協議済みの最小候補、得点率・平均点の式・平均点／集団の得点率による分岐は採用する実装回を別途決める。各回は設定から判定、保存、三つの出力までを一貫して完成させる。未採用の種類を利用可能な選択肢として表示しない。

Q3は確定済みであり、集団の得点率は既存の順位集計結果を使う。異なる満点の混在に専用計算や設定禁止を追加せず、その違いだけで処理を停止しない。ソースの精度・単元・確定済み集計の接続は技術上の確認事項として残る。

## 1. 複数ルールの設定・保存を可能にする

**Main Screen:** [成績入力設定] - `/admin/grade_report_setting/manage`

**Affected Screens:**

- [成績集計] - `/admin/grade/grade_setting_system/grade_calc`
- [成績公開設定] - `/admin/grade_report_setting/grade_publish`

**変更範囲:** 機能へのアクセス権および対象項目の編集権を持つ教員向けに、入力欄設定から赤点設定一覧、適用条件、基準設定へ進む画面と保存処理を追加する。共通フォーム、非集計型フィルタ、固定点数と採用する得点率の設定を本Taskが担当する。集計型の追加部分はTask 3、再実行はTask 4、公開設定はTask 6の依存先であり、ここで出力実装を重複させない。

### 業務変更

- 項目・入力型・学期／時期を示し、名称、優先順位、保存済み条件・基準の要約、追加・削除・並べ替えを提供する。名称は識別の補助であり、データの結合キーにしない。数値型以外に有効な赤点設定を作成しない。
- 対象は項目の許可範囲全体、または対応済みの教科／科目・学年・学級／グループ・選択条件で限定する。同一フィルタ内はOR、異なるフィルタ間はANDとし、A/B/C項目自体は判定しないが対象を絞る選択条件には利用できる。
- 固定点数は保存時に全適用対象で `0≤N≤M` を満たすことを確認し、対象拡大時も再検証する。得点率は `0≤N≤100`、最終比較は未満／以下。不要な集計参照元を要求しない。
- 保存・並べ替え・削除は設定だけを変更し、判定完了とは表示しない。最後の設定を削除しても既存結果は再実行まで保持し、再実行が必要なことを伝える。取消し・保存失敗は保存済み設定と結果を維持する。
- **設計案としてreviewする部分:** 新規は末尾に追加し、固定点数・未満・値未入力で開始する。不完全な追加行は有効にせず、対象限定なのに有効なフィルタがない場合はエラーにする。同一編集内の種類切替は入力を一時保持し、再表示では保存した種類を復元する。参照先変更時は無効な従属選択だけを解除する。

### 技術対応

- 既存の自動計算設定の制御処理 の `edit`、`editCondition`、`registCondition`、`editFormula`、`registFormula`、`sort`、`delete` は既存の一覧・条件・式・保存の参考箇所。適切なフォーム部品と検証を再利用し、既存のAutoRating設定そのものを赤点ルールへ転用しない。既存画面にある特定校向け機能制限を、新機能の共通要件として複製しない。
- アプリケーションの画面ルーティング設定 にある入力欄設定の入口と接続し、新規画面URL・HTTPメソッド・保存契約を実装設計で定める。画面表示と保存の双方で学校・年度・項目編集権・選択した参照先の所属を確認し、CSRF、server validation、名称や記号の出力escapingを保つ。
- Task 2が定める設定保存先に、順序・対象・現在選択中の基準・比較・端数処理を保存する。保存失敗時の部分更新を防ぎ、成功後の読戻しはレプリカ遅延で旧値へ戻らない方法を採る。既存の `red_score`／`changed_red_score` を更新・初期化しない。
- 満点の検証はTask 2の実効満点取得を共用する。固定値の妥当性は保存時の確認であり、後日満点が下がっても保存済み固定値を自動補正する処理は入れない。
- ruleの追加・編集・削除・並べ替えでは、所有する `grade_evaluate_frame_items` 行をlockし、`red_score_revision` の増加と設定保存を同transactionで行う。最後のrule削除でも版数を進めるが、前回判定を消さない。Task 2はこの版数を保存前に照合する。

### 依存・未確定

設定項目・遷移・validationの設計は開始できる。保存実装にはTask 2のデータ契約が必要。初期表示、追加途中、種類切替の詳細は上記設計案のreviewを行う。平均／集団得点率に関するフィールドの追加はTask 3が担当し、同じフォームへの変更順を調整する。

### 完了の要点

権限を持つ教員が対象の数値項目に複数ルールを設定し、再表示で内容と順序を確認でき、設定保存と判定更新の時点を区別できる。

## 2. 最終点数を判定し、共通結果を保持する

**Main Screen:** 直接画面なし。判定・保存・読取りの共通処理。

**Affected Screens:**

- [成績入力設定] - `/admin/grade_report_setting/manage`
- [成績集計] - `/admin/grade/grade_setting_system/grade_calc`
- [成績抽出] - `/admin/nb/grade/grade_setting_system/grade_extraction`
- [成績確認] - `/student/grade/grade_publish`
- [通知表ツール] - `/admin/grade_report_setting/report_card`

**変更範囲:** 権限確認済みの処理対象について、設定・結果のDB設計、実効満点取得、ルール選択、固定／採用する得点率の判定、状態保存と共通読取りを担当する。各画面は依存consumerであり、個別の表示変更はTask 5〜7が所有する。旧赤点を読む学校別帳票は回帰確認対象とする。

### 業務変更

- 生徒・学校・年度・授業／科目・項目・学期／時期・単元を保った一つのセルに、一つの現行結果を対応付ける。最終保存点 `S` を使い、手入力・見込点・未受験の数値・有効な0も判定する。空欄や無効な点数を0にしない。
- 優先順に対象条件を確認し、最初に一致したルールを選んでから基準を計算する。上位ルールの条件を判定できない場合や、選択済みルールの基準を計算できない場合は下位へ進まない。非集計条件だけで対象外が確定すれば、そのルールの集計は読まずに次へ進める。
- 固定は `T=N`。得点率は現在の実効満点 `M` に対する `M×N/100` に選択された端数処理を行う。満点は項目の標準値→単元の有効な例外→実際に適用する授業の選択による上書きの順で解決する。率の判定には正で有限の満点が必要だが、固定の計算は後日の満点に依存させない。
- 赤点／非赤点／未判定／判定不能／適用なし／点数なしを区別する。設定・参照元だけの変更中は前結果を保持し、再実行で基準不成立なら判定不能、全ルールが対象外なら適用なしへ更新して旧結果を停止する。点数削除・無効化では旧数値の表示・絞込みを残さない。
- 判定は点数を変更せず、三出力が同じ現行結果を読む。再実行は結果や記号を重複させず、遅れて完了した旧処理が新しい点数・結果を上書きしない。

### 技術対応

- 評価フレームに基づく共通成績取得処理 は項目、授業、生徒、学期／時期、単元を含む点数の読取り箇所。共通結果をこのデータ経路へ結び付けるか、同じ識別を持つ読取りを接続する。画面の列番号や項目名をキーにせず、点数レコードの削除・再作成を判別する。
- 既存の自動計算処理 の `calcPerStudent` は標準・単元・選択効果の順で満点を解決し、計算後の点数をmin/maxへ制限する。満点解決だけを参考にし、基準 `T` にはその点数補正や `createRegistData` の書込みを適用しない。既存の点数範囲取得処理 単独では単元の段階を満たさないため、そのまま全対象対応としない。
- **設計提案:** 新しい設定と結果を旧scalarから分離し、セル識別・現行状態・使用ルール／処理・時刻、必要な判定根拠を保存する。削除したルールの結果を再実行まで読める関係を設計し、削除時の連鎖削除に依存しない。物理テーブル、精度、index、更新順序は本Taskで設計reviewに出す。全ruleのversion管理や履歴画面は追加しない。
- 比較 `S=T`、有限性、overflow、保存・読戻し精度を共通で保証する。任意コードを実行せず、既存model／repositoryと一括取得を使い、query-in-loopを避ける。writerとconsumerの整合性、重複実行・古い処理の更新拒否を既存transaction／job方式で具体化する。
- Task 3からは参照値と式の計算結果／判定不能理由を受け、現行結果の保存と失効は本Taskに集約する。Task 4は起動・対象集合・transaction境界を接続し、各出力は判定を再計算しない。
- **v2の保存方式:** `red_score_results` にセル世代、予約版数、完了版数、使用rule版数を保持する。frame-item → 授業の `groups` 行 → セル制御行 → 点数行の順でlockし、入力取得前に予約する。保存前に世代・予約・rule版数と点数行を照合し、不一致や完了済みticketを更新しない。初回制御行のNULL payloadは未判定。異なる項目が同じ物理点数行を新規作成する競合は授業行の共通lockで直列化し、取得後に現行行を読み直して待機中に作られたIDを再利用する。
- 空欄化・論理削除・再作成は同じ点数IDでも世代／版数を進め、旧判定を停止する。削除後は制御行を残し、復元先へ旧tokenを移植しない。待機中の予約版数差だけでは前回完了結果を失効させない。これは現在の整合性制御であり、全ruleの履歴管理ではない。

### 依存・未確定

セル識別、状態、固定／得点率の設計は実集計ソースを待たず開始できる。DB設計と数値精度を確定してから保存実装を完成させる。Task 3の参照元や式が未統合でも、独立ルールまで一緒に保留しない。DB設計完了は実装・migration実行の完了とは区別する。

### 完了の要点

点数を変えずに正しいセルの状態を一意に保存し、設定削除・判定不能・適用なしの前後を三出力が同じ意味で読み取れる。

## 3. 集計を参照する条件・式を利用可能にする

**Main Screen:** [成績入力設定] - `/admin/grade_report_setting/manage`

**Affected Screens:**

- [成績集計] - `/admin/grade/grade_setting_system/grade_calc`

**変更範囲:** 採用が決まった平均点／集団得点率の適用条件と式について、Task 1のフォームへの追加、入力保存・検証、参照元の解決、式評価を担当する。対象項目編集権と参照先の学校／年度を守る。既存の集計操作は必要な依存であり、新しい順位集計方式は作らない。

### 業務変更

- 集計対象時期、順位集計設定、集計対象（母集団）と、正しい科目・項目・単元を指定する。適用対象と参照母集団を分け、抽出時の生徒絞込みで平均値を変更しない。条件だけが平均／率を使う固定点数ルールも参照型として扱う。
- 母集団の選択肢は既存の学校／年度の集計設定に従う。学年・HR・授業は対応する集計が有効な場合だけ選択可能とし、赤点側に集計スイッチを追加しない。同じ順位集計設定Xで対象母集団の結果を参照し、種類を変えるためだけに別設定を作らない。有効でも結果がなければ判定不能とする。
- 確認済みのAに従い、順位集計グループ・組み合わせグループ・科目グループは既存設定があれば上記3つの有効化フラグと独立して選択・保存できる。名称で選択しIDを保持する。成績公開設定と同様に順位集計設定→集計対象の順で選び、条件と式に同じ選択動作を提供する。例示画面の順位・表示名・グラフ設定や、科目別母集団を編集する新画面は追加しない。
- 該当する確定済み集計を自動優先し、存在しない場合だけ同範囲の最新の完了済み集計を使う。選んだ確定済み集計の欠損を別の集計で埋めず、未集計点から平均を作り直さない。
- 分岐には丸める前の平均 `A`／集団の得点率 `R` を使う。`A=49.99` は `<50`。`R` は既存集計の同じ寄与集合に基づく総得点／総満点を引き継ぎ、個人率の単純平均や対象生徒の `A/M` に置き換えない。
- 式は行ごとの左右の値、四則演算、端数処理で構成する。前行結果はその行の端数処理後の値を参照し、最後の行を `T` とする。有限な負の基準は有効で、0や満点に制限しない。固定の0除算・欠けた値・前方／自己／削除済み行参照は保存時に拒否し、実行時の0除算・欠損・非有限値はTask 2へ判定不能として渡す。
- **設計案としてreviewする部分:** 分岐の比較は `<`／`≤`／`≥`／`>`、式の値は平均・固定値／係数・前行結果とする。式内の平均は一つの参照元、適用条件は独立した参照元選択を持つ。端数処理位置は `p=1..9`（小数第p位を処理）、方法は四捨五入・切り上げ・切り捨て。負数では四捨五入は半分を0から遠ざけ、上／下はceil／floorとする。

### 技術対応

- 既存の集計結果取得処理 は集計設定・母集団・科目・時期から値を取得する既存接続点。現在の読取りをそのまま確定済み・単元対応とせず、必要な単元識別と確定済みソースの選択を最後まで引き継ぐ。
- 総得点・人数・総満点を同一集計と同一寄与範囲で確認する。平均の人数を順位対象人数に置換しない。率の丸め済み表示値だけで比較せず、必要精度の値またはその構成値を取得する。人数0、不正な分母、欠損を実在の0として扱わない。
- 自動計算設定の制御処理 の条件・式編集と 既存の自動計算処理 の `calcResult`、`getCalcValue`、`calcDecimalPlace` を参考にする。任意の既存operandを全公開せず、判定用の式は点数の保存・NULL化・min/max制限から分離する。行の削除／移動後は参照の意味を検証する。
- 設定はTask 1の保存経路、式の結果はTask 2の判定・保存契約へ接続する。同じ参照元を複数回使う処理では同じソースを使い、条件側の参照元変更で式側を暗黙変更しない。数値桁数、係数範囲、行数上限は実装設計で定め、受理した値を保存時に黙って丸めない。
- `GradeCalcResultService::createPopulationList` と `GradeCalcDetailConf_m` の学校／年度設定をもとに、表示とserver保存検証で同じ利用可否を使う。授業はセルの授業IDに対応する結果を読む。科目グループは `getUseTargetPopulation` と同様に科目別指定/defaultを解決し、選択IDと解決後の母集団を保持する。名称による代用、別授業の結果、欠損時の別母集団への切替を許可しない。適用条件と式の両方、copy／年度対応付けを同じmappingに揃える。

### 依存・未確定

### 技術対応

- 授業の直接入力による成績登録処理 と CSVによる成績登録処理 は点数保存→AutoRating→transaction完了→順位集計の接続点。既存の許可された時期と対象セル集合を使い、点数の成功通知前に対応する結果保存を整合させる。
- 試験採点結果の成績連携処理 は点数を書いた後、`createArgument` に授業が含まれなければAutoRatingをskipする。判定を `AutoRating::calc` の内側だけへ追加せず、この経路の書込み済みセルも処理する。
- 自動計算の実行処理 は自動計算後にも主副科目・観点コピー・単位更新を実行する。途中値で判定せず、関連更新先を含む最終セル集合を確定する。既存の「式なしreturn」「手入力skip」「対象外でNULL保存」を判定の除外条件や点数削除として流用しない。
- 一括計算の対象組立て処理、一括処理の進捗保存処理、成績集計の制御処理 と 成績集計画面 で、起動可否・対象組立て・進捗を一貫させる。式の有無だけに依存せず、最後のルール削除後の結果整理も可能にする。
- 一括処理の原子的な全件rollbackは前提にしない。Task 2の重複／順序制御と既存jobの復旧方式を接続し、成功・業務上の判定不能・保存失敗を区別する。新しいqueue基盤や全校lockは要求しない。
- `AdminNBGradeSettingSystemLessonController`／CSV controller／`ScoringResultService` は点数や依存選択値を書き込む前にTask 2のlockを取得する。transaction前に取得した点数を判定の正本にせず、lock後に必要な現行値を読み直す。`AutoRating::saveGradeToParentSubSubject` 等の関連入力・更新先も対象に含める。
- 判定のみのbatchは予約transactionと条件付保存transactionを分けられる。点数も書くbatchでは入力取得から点数書込までの保護も必要で、古い点数を書いてからticketを作らない。世代／版数不一致は旧処理として破棄し成功件数に含めない。deadlock／timeoutはtransactionをrollbackし、既存の有限retryまたは失敗範囲の再実行案内を使う。

### 依存・未確定
